# CRY1 (7DLI) — reproducible loop modelling + MD

A self-contained workflow that prepares the *Drosophila* cryptochrome CRY1
receptor (from PDB **7DLI**) with a docked ligand, models a disordered
pocket-adjacent loop with **Boltz-2**, and runs an explicit-solvent MD simulation
with the **OpenFF/OpenFE** toolchain. The prepared system is reusable for
free-energy perturbation (FEP) in the same framework.

See [`md_workflow.md`](md_workflow.md) for the full methods write-up.

## What it does

1. **Identify the missing loop.** The receptor has a physical chain break between
   Ser395 and His396 (14.8 Å Cα–Cα) that is numbered over in the file. Aligning
   chain B to the deposited 7DLI sequence shows six disordered residues,
   **Phe-Phe-Gln-Gln-Phe-Phe (FFQQFF)**, belong there.
2. **Model the loop with Boltz-2 in the ligand-bound (holo) state.** Boltz
   co-folds the protein together with the 7dli ligand, conditioned on the
   deposited `7dli.cif` template, run single-sequence (no external MSA server),
   with a pocket constraint that places the ligand in the crystallographic site.
   Because Boltz builds the loop against both anchors it closes on both ends, and
   because the loop is only ~7 Å from the pocket it must be built holo — with the
   ligand present the loop shifts ~2 Å (up to 3.5 Å) relative to the apo model.
   Boltz recovers the crystal binding mode (ligand ipTM 0.96; co-folded pose
   within ~1 Å of the docked pose).
3. **Graft only the six loop residues** into the crystal receptor (insertion codes
   395A–395F), preserving the experimental binding-site coordinates,
   crystallographic waters and residue numbering.
4. **Prepare + simulate** with OpenFE: PDBFixer (drop a stray free lysine, keep
   waters, add H), ligand AM1-BCC charges, Amber ff14SB + OpenFF Sage + TIP3P,
   then minimize → NVT → NPT → production.

The receptor is a single protein chain: 7DLI's three crystal chains are identical
copies (not a biological oligomer — an assembly prediction gave interface
ipTM ≈ 0.16), and the pocket is fully intramolecular, so the monomer is the
correct simulated unit.

```
7dli_md_repro/
├── README.md                  this file

├── environment-boltz.yml      conda/mamba env for loop modelling (Boltz-2)
├── run_all.sh                 runs the whole pipeline end to end
├── inputs/
│   ├── recfinal_7dli_water.pdb   receptor (chain B) + crystallographic waters

│   └── 7dli.cif                  deposited structure (Boltz template + sequence)

│   └── 4_run_md.py               protein prep + MD (OpenFE)

```

## Requirements

- Linux with an NVIDIA GPU (tested: RTX 4000 Ada, 20 GB, driver 550 / CUDA 12.4).
- `conda`/`mamba` (miniforge recommended).
- ~4 GB disk for the two environments plus ~6 GB for Boltz-2 weights (structure + affinity models + CCD)
  (downloaded on first run to `$BOLTZ_CACHE` or `~/.boltz`).

## Setup

```bash
mamba env create -f environment-md.yml      # creates env "openfe"
mamba env create -f environment-boltz.yml   # creates env "boltz"
```

Two environment notes for this hardware (CUDA 12.4 driver):

- **PyTorch (boltz env).** The pinned build is `torch==2.6.0+cu124`. If a
  freshly resolved env pulls a newer CUDA build that reports
  `torch.cuda.is_available() == False`, reinstall the matching wheel:
  ```bash
  mamba run -n boltz pip install "torch==2.6.0" --index-url https://download.pytorch.org/whl/cu124
  ```
- **OpenMM platform (md env).** If the OpenMM CUDA platform fails with
  `CUDA_ERROR_UNSUPPORTED_PTX_VERSION`, the MD runs on **OpenCL** on the same GPU
  (`COMPUTE_PLATFORM = "OpenCL"` in `scripts/4_run_md.py`). Set it to `"CUDA"`
  once your OpenMM/CUDA build matches the driver, or `"CPU"` to force CPU.

## Run

```bash
bash run_all.sh
```

Override env locations if your envs are named differently:

```bash
MD_PY=/path/to/openfe/bin/python \
BOLTZ_PY=/path/to/boltz/bin/python \
BOLTZ=/path/to/boltz/bin/boltz \
bash run_all.sh
```

Or run the steps individually (see the header of each script in `scripts/`).

## Outputs

- `outputs/recfinal_7dli_water_loopmodelled.pdb` — receptor with the loop grafted
  in (insertion codes 395A–395F).
- `outputs/recfinal_7dli_water_loopmodelled_fixed.pdb` — after PDBFixer (stray
  lysine removed, waters kept, hydrogens added).
- `outputs/boltz_out/…/boltz_7dli_model_0.pdb` — the Boltz-2 loop model.
- `outputs/md/shared_PlainMDProtocolUnit-*/` — `system.pdb`, `minimized.pdb`,
  `equil_nvt.pdb`, `equil_npt.pdb`, `simulation.xtc`, `simulation.log`.

## Tuning

- Increase `NVT_NS`, `NPT_NS`, `PROD_NS` at the top of `scripts/4_run_md.py` for
  production-quality sampling (defaults are short so the demo finishes quickly).
- The modelled loop is a single moderate-confidence conformation of a flexible
  region; for quantitative work, sample it (multiple models / longer
  equilibration) rather than trusting one pose.
- Boltz-2 is stochastic, so the raw graft junction C(395F)–N(396) varies run to
  run (~1–3 Å); `scripts/3_graft_loop.py` prints it. OpenMM's minimization (the
  first MD step) closes junctions in that range to a normal ~1.33 Å peptide bond,
  and the loop is continuous after equilibration. If a run ever produces a much
  larger junction, add `--diffusion_samples 5` to the Boltz call and graft the
  sample with the smallest junction.
